# _REPORTS — 00_Cerebrum

Register of every report in this folder. `Raw/` has `_INGESTED.md` and each `Wiki/` has `index.md`; this is the equivalent for query history, so a future session can see what has already been asked before asking it again.

One register for the whole vault. A per-knowledge-base split answers a question the corpus does not ask: a report spanning two knowledge bases then has no correct home. **Scope** carries what a folder would.

One row per report, newest first. Written at the same time as the report, never retrospectively.

Two kinds of row. **Question reports** answer something asked of the corpus. **Audit reports** come from a health check and are never promoted, because process history is not knowledge about the subject.

**Promotion** records whether the report's synthesis became a concept. The values are `promoted`, `partial`, `none` and `pending review`.

| Date | Scope | Question or audit | Report | Drew on | Promotion |
|---|---|---|---|---|---|

## What this register is for

1. **Avoiding repeated research.** Start from the report, not from the archive.
2. **Finding promotion candidates.** A report with synthesis that no concept holds is a candidate.
3. **Spotting repeat questions.** The same question asked twice is the strongest signal that a concept is missing.

A question that required reading a chunk of uncompiled archive usually produces a report worth promoting, because the reading was the expensive part and the concept is nearly free.

## Rule

Every report gets a row when it is written. A report with no row is invisible, which defeats the point of filing it.
